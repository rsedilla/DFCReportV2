# 2026-11-09 — The Admin's page for one person is three views

An Admin's page for one person stacked what is known of the person beside everything that can be
done to their account, in one long column, with Merge at the foot. The owner found it fragmented,
and chose from screenshots of today and the proposal.

## The ruling

**Under the page's actions, a switch chooses *Overview*, *Account* or *Who opened*, each keeping its
address.** *Overview* holds DCC, Growth, the Cell and the details. *Account* holds the account and
its ticks, then each sign-in action on a row with its reason, then *Is this person recorded twice?*
and *Archive*, which moves here from the page's actions. *Who opened* holds the log of decision 0414,
which is read only when opened. Somebody offered only *Overview* sees no switch.

Archive, where something stands in the way, is shown greyed with what to resolve first beside it.

## Why

What a person is gets looked at constantly and what can be done to their login rarely, so the second
waits behind a choice. It is a switch rather than tabs because the page already sits under People's
tabs, and a choice inside a tab is a pill.

No capability changes. Each view shows what the same reader was already offered, and the API still
decides every request.
