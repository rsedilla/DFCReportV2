# 2026-09-22 — No list of details to collect; the person's record offers to add one

Birthday became optional on 2026-08-24, and the open item beside it asked whether a leader
sees a list of the people whose birthday or mobile number is missing, on the ground that an
optional field nothing surfaces never gets collected. The owner's Claude Design has no such
list. The owner chose this answer from a drawing of it beside a People-screen filter.

## The ruling

**No list is offered**, on any screen.

**The person's record offers to add a detail that is not recorded.** Beside "Not recorded"
for a birthday or a mobile number, an "Add" link opens the edit form on that field. It is
shown only to a reader holding `people.edit_basic`, and the API still decides whether the
edit is allowed.

## Why

Section 3 made the birthday optional so that a church does not press the people most
guarded about their details. A list of who has not given one presses them, and keeps
pressing: somebody who declined stays on it until the separate question of recording
"asked, not given" is settled. A link on the record is seen only by a leader already looking
at that person.

Nothing new is stored and the API is unchanged.
