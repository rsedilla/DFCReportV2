# 2026-10-01 — A Member ID or Cell ID is shown on its own page and where one is chosen

Lists showed a Member ID under every person's name and a Cell ID under every Cell's, which
the owner found hard to read. Asked on 2026-10-01, the owner chose to show each identifier
only where it is needed, from an audit of every screen showing one.

## The ruling

**1. A screen shows a Member ID or a Cell ID in two places only:** on the person's or the
Cell's own page, and where somebody must choose between people or Cells that may share a
name — the person picker, the Cell picker, and Add a Person's possible duplicates.

**2. Everywhere else a person is shown by name and a Cell by its category and meeting day,**
where the screen is given them, with the leader's name where the screen already gives it. A
sentence that named a Cell by its ID names it the same way.

**3. Nothing about the identifiers themselves changes.** They are still assigned, never
reused, carried by the API, used by printed reports, and found by a search: the People
screen still matches a Member ID by prefix (decision 0259) whether or not the row shows it.

## Why

The identifiers are handles for staff, reports and conversation (Sections 3 and 10). On a
list a name already does that job, and the pastoral leader or the Cell's leader beside it
tells two people or two Cells of one name apart. Where nothing beside the name does, which is
a church-wide pick or a duplicate check, the identifier stays.
