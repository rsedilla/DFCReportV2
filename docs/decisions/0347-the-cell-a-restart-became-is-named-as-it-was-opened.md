# 2026-10-14 — The Cell a restart became is named as it was opened

Closed Cells' *Restarted as* named the new Cell by its present category and day, so a reader
whose branch covers the closed Cell kept seeing the new Cell's details after it was handed
outside that branch. The owner chose this answer on 14 Oct from real screenshots of four
options, as option C.

## The ruling

**The new Cell is named by the category and day of the approved request that minted it**:
"Restarted as Couple · Wed". Approval creates the Cell from its request's own category and
day, and a decided request is never rewritten, so this is the new Cell as it was opened. It
does not follow the Cell after it changes its day or is handed to another leader.

**A restarted Cell with no approved request behind it is named by its Cell ID.** Every
restart goes through a request (Section 10), so this is a fallback rather than a case the
screens expect.

## Why

It keeps a name on the list, which decision 0306 asks for, and shows nothing about the new
Cell that was not true when it opened. Rejected: the present details (the disclosure above),
the Cell ID (against 0306), and the word alone (it no longer says which Cell it became). No
migration is needed: the request already holds the values.
