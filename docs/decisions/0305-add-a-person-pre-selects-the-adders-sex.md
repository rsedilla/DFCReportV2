# 2026-09-29 — Add a Person pre-selects the adder's sex

Add a Person asks for the new person's sex with nothing chosen, and its Pastoral leader box
already starts on the person adding, where they hold an assignment or a root seat (owner's
design of 2026-09-19). A leader leads only within their own Network
(Sections 4 and 5), so when that default leader is kept, the only sex the server accepts is
the leader's own. The owner approved pre-selecting it on 2026-09-25, with nothing pre-selected
for administrators and the two Senior Pastors, who add people to both Networks.

## The ruling

**1. The Sex choice starts on the adder's own sex when the adder holds a pastoral assignment
under a leader.** It stays an ordinary choice: the encoder can change it before saving, and
the Network is shown beside it as Section 4 already requires.

**2. Nothing is pre-selected for a Network root or for anybody holding no pastoral
assignment.** In practice these are the two Senior Pastors and an administrator outside the
tree, who add people to both Networks.

**3. It is decided by the adder's place in the tree, never by their account's role.**
Whether a screen may key anything on the role `GET /auth/me` names is open in `CLAUDE.md`,
and this does not settle it. The tree already decides the Pastoral leader default on the same
screen.

## Why

It removes a click from the common case, and the value it starts on is the only one the
screen's own default leader can accept. The cost is that a default can be saved unread,
which Section 4 warned about for the Network. It is accepted because the encoder still sees
the choice with the Network beside it, and a sex recorded in error has an audited remedy:
correcting a person's sex.
